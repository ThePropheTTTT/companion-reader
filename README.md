# 陪读

有人陪着读书的 AI 阅读器。导入 EPUB，它先粗读一遍，在部分段落边上留几句像书评的话；
太安静了就一键放一波弹幕；想聊两句就打开「书搭子」——它读到的进度和你完全一样，绝不剧透。

为**看不进去书的人**做的，不是为"读完多少本"做的。所以它默认只做三件事：
**陪你读、别剧透、别装**。

## 跑起来

```bash
npm run dev          # http://127.0.0.1:5178（真机调试看控制台打印的局域网地址）
```

零依赖：不需要 `npm install`，`package.json` 里没有 `dependencies`。

### 放到网上（iOS 需要 HTTPS）

**这个仓库已经配好了 GitHub Pages**：推到 `main` 就会自动部署，
地址是 https://theprophetttt.github.io/companion-reader/ ——
在 iPhone 上用 Safari 打开 → 分享 → **添加到主屏幕**，就有了独立图标、
离线可用、没有地址栏。（工作流在 `.github/workflows/pages.yml`，
跑之前会先执行 `npm run verify`，部署失败总比发一个白屏好。）

也可以换成任意静态托管，`site/` 目录就是全部产物：

```bash
# Cloudflare Pages / Vercel / Netlify / 自己的 nginx，都只是"托管一个目录"
# 例：Cloudflare Pages 直接把 site/ 作为输出目录
```

Service Worker 在 `https` 或 `localhost` 下自动注册（局域网 IP 的 `http://`
不是安全上下文，注册会静默跳过）。所有路径都是相对的，所以放在子路径下也能用。

## 它有什么

| 能力 | 说明 |
|---|---|
| 导入 | EPUB 为主（TXT 也认）。**全程本地解析**：ZIP 用浏览器原生 `DecompressionStream` 解，不引任何 CDN |
| 仿生锚点 | 中文语义小句锚定：只锚"小句第一个字"和"长句内容段第一个字"。强度 0~4 可调 |
| 分页 | 测量式分页（整章渲染 → 量真实高度 → 贪心装箱 → 只渲染当前页）。不用 CSS 多栏，因为 Safari 在 `100dvh` 里分栏不可靠 |
| 批注 | 导入后后台预生成，**读到的那一刻它已经在那里**；质量闸门挡掉"这段描写细腻"式废话 |
| 弹幕 | 一键放一波（不是常开开关）。4~12 字，位置按段落算而不是按页码算 |
| 书搭子 | 就当前页 + 已读内容聊天。三级上下文压缩：更早的章→梗概、本章前文→原文、当前页→全文 |
| 语音 | 系统 TTS 朗读 + 语音输入。系统不支持就**不显示按钮**，而不是显示一个点了没反应的 |
| 排版 | 宋/黑/楷、四种主题、字号行距段距行宽、亮度 |

### 剧透是唯一的红线

`spoilerPi` = **用户实际翻到过的最远那一段**（往后翻才推，往回翻不推，只增不减）。
送给模型的上下文里，`spoilerPi` 之后的内容一个字都不出现，**包括后面章节的标题**
（标题本身就是剧透）。这条有专门的回归测试钉着：`test/companion.test.js`。

prompt 里也刻意不说"不要剧透"——那句会被理解成"可以暗示"。改成正向表述：
"你和这个人读到的进度完全一样"。

## AI 怎么配

设置 → 右上角「✦」。支持 DeepSeek / 月之暗面 Kimi / OpenAI / 任意 OpenAI 兼容端点。

**密钥只存在你这台设备的 IndexedDB 里**：没有后端、没有中转、没有遥测，
请求从浏览器直接发往你填的那个地址。这一点也写在设置面板上，
因为把 key 粘进一个网页是需要信任的动作。

费用可控：粗读用便宜模型，只对筛出来的少数段落深写；章节梗概与人物表作为稳定前缀，
命中服务商的 prompt cache。

```
  css/          设计变量 + 各模块样式

test/           148 项测试
CONTRACT.md     模块之间的接口契约 + 踩过的坑（改代码前先看它）
```

## 自检

```bash
npm run verify        # 静态自检 + 全部单测（不需要浏览器）
node tools/fake-ai.mjs &   # 假模型服务：确定性回答 + 录下每个请求
npm run smoke         # 开一个 headless Edge，把一本书真的读一遍（需要非沙箱环境）
```

三段各管一段，缺一段就有盲区：

- **`check`**：模块能不能加载、import 有没有断、资源在不在、SW 预缓存清单是否和实际文件对得上。
  这个项目没有构建步骤，所以"拷目录就是部署"——写死的本机地址、少一个图标，只会在服务器上暴露。
- **`test`**：148 项单测。解析、锚点、分页数学、存储键名、剧透线。
- **`smoke`**：唯一能回答"屏幕上有没有字"的一层。它抓到过整章挤成一页、翻页后空白、
  书架点不开、空 `src` 的 404 —— 这些 bug 发生的时候，前两段全是绿的。

`smoke` 里带 AI 的那一段（配好 Key、生成批注、弹幕、书搭子对话、断网重开）需要一个假模型服务：
用真 API 测不了，因为每次回答都不一样，断言写不死。`tools/fake-ai.mjs` 给确定性回答，
并把**每个收到的请求原文**录进 `.fake-ai/requests.jsonl` —— 于是「送出去的上下文里有没有剧透」
这种事可以拿断言钉住（读 prompt 自我安慰不算验证）。截图落在 `.shots/`。
